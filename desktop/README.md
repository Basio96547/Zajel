# نسخة الكمبيوتر (Compose Desktop)

عميل كامل الأهلية: هوية خاصة به، يرسل ويستقبل من وإلى الهاتف في الاتجاهين.
ليس «مرآة» للهاتف — هو جهاز مستقل يقترن بالـ QR مثل أي هاتف آخر.

## لماذا يتوافق مع الهاتف

كل ما يسير على السلك يأتي من وحدة `:core` — نفس الكود المُصرَّف حرفياً على
المنصتين:

| في `:core` (مشترك) | خاص بكل منصة |
|---|---|
| `SignalProtocol` (Double Ratchet + X3DH) | التخزين |
| `PqKem` (ML-KEM-768) | الاكتشاف (NsdManager / jmDNS) |
| `Envelopes` (شكل المغلفات + توقيع الحزم) | الواجهة |
| `MailboxToken` / `RelayBlob` (الوسيط الأعمى) | تحميل libsodium |
| `MessagePadding` / `AckToken` / `B64` | |

الفصل مقصود: **السلوك قد يختلف بين المنصتين، الصيغة لا.**

## التشغيل

```bash
gradlew :desktop:run
```

للحزم كمثبِّت مستقل (‎.msi‎ على ويندوز):

```bash
gradlew :desktop:packageDistributionForCurrentOS
```

الوسيط الأعمى قابل للتغيير أو الإلغاء وقت التشغيل. تركه فارغاً = شبكة محلية
فقط، لا شيء يغادر الـ LAN إطلاقاً:

```bash
gradlew :desktop:run -Dsecuremessenger.relayUrl=
```

## الاقتران (لا بدّ من الاتجاهين)

الاقتران **متبادل**. اقتران باتجاه واحد يبدو ناجحاً ثم يحمل الرسائل في اتجاه
واحد فقط — وهذا أحد أكثر أسباب «لا تصل الرسالة» خداعاً.

1. اضغط **+** في نسخة الكمبيوتر → يظهر رمز QR.
2. من الهاتف: «محادثة جديدة» → «مسح رمز صديق» → وجّه الكاميرا للشاشة.
3. **والعكس**: من الهاتف «مشاركة رمزي كصورة» → انقل الصورة للكمبيوتر →
   في نافذة الاقتران اضغط «فتح صورة الرمز». أو الصق نصّ الرمز مباشرة.

الكمبيوتر لا كاميرا له غالباً، ولذلك يقرأ رمز الهاتف من صورة أو من نص.

## إن لم تُكتشف الأجهزة تلقائياً

الاكتشاف التلقائي (mDNS) هو أهشّ حلقة في السلسلة: كثير من الراوترات تمنع
البثّ المتعدد بين الأجهزة (AP isolation)، وشبكات الضيوف تحجبه أصلاً.

المخرج: **العنوان المباشر**.

- عنوان هذا الكمبيوتر يظهر أعلى القائمة اليسرى، ومثله في نافذة «عنوان مباشر».
- على الهاتف: معلومات جهة الاتصال → «حالة الاتصال» → اكتب `‎192.168.1.20:47601‎`.
- على الكمبيوتر: زر «عنوان مباشر» في أعلى المحادثة.

العنوان **دلالة فقط**: من يردّ عليه يبقى مضطراً لإثبات هويته بالمفتاح
المثبَّت (TOFU من الـ QR)، فعنوان خاطئ يمنع الاتصال ولا يسرّب شيئاً ولا
يوصل رسالة لغير صاحبها.

## الاختبارات

```bash
gradlew :desktop:test
```

عميلان حقيقيان، مقبسان حقيقيان، محادثة حقيقية: اقتران متبادل ← تحدٍّ ←
حزمة مفاتيح موقّعة ← X3DH+ML-KEM ← تعمية ← WebSocket ← فكّ ← إشعار استلام
موثَّق. بالإضافة إلى دورة كاملة على ملف التخزين المشفّر. لا يحتاج جهازاً.

> **إن رأيت `gradlew :desktop:testDirect` في وثيقة أقدم:** تلك المهمة حُذفت في
> 2026-07-31. وُجدت لأن المشروع كان يسكن مساراً بأحرف عربية، فكان عامل اختبار
> Gradle يفكّ مسار الأصناف بترميز ويندوز القديم لا UTF‑8، فتصير كل المداخل
> مسارات غير موجودة ويموت كل شيء بـ`ClassNotFoundException` رغم أن الأصناف
> مُصرَّفة سليمة. نُقل المشروع إلى مسار ASCII فصار `test` القياسي يعمل، وحُذفت
> المهمة البديلة بدل إبقائها «احتياطاً» — طريق ثانٍ لتشغيل الاختبارات لا أحد
> يحتاجه سيبتعد بصمت عن الأول.

## فروق مقصودة عن الهاتف

- **لا تمويه الآلة الحاسبة.** التمويه موجود لأن الهاتف يُلتقط ويُتصفَّح؛ هذا
  التهديد لا ينتقل إلى كمبيوتر، ونافذة حاسبة وهمية كانت ستضيف سطحاً مربكاً
  بلا حماية مقابلة.
- **الحماية بعبارة المرور لا بعتاد الجهاز.** على الهاتف يحمي المفتاحَ
  Android Keystore. لا يوجد مقابل موحّد عبر ويندوز/ماك/لينكس، فالمفتاح
  مشتقّ من عبارة مرور عبر Argon2id. **النسخة المكتبية قوية بقدر قوة تلك
  العبارة**، وتبقى مفتوحة ما دام التطبيق يعمل. هذا مكتوب صراحةً في شاشة
  الإنشاء.
- **نصّ فقط في هذا الإصدار.** الوسائط والرسائل الصوتية تُستقبل وتُشعَر
  بالاستلام (فلا تعلق في صندوق صادر الهاتف) لكن لا تُعرَض بعد.
